# Document-processing data flow

1. **Upload.** The browser sends UTF-8 TXT or text-based PDF bytes to loopback `POST /api/review`. The backend bounds the request at 8 MiB. Extraction is limited to 100,000 characters and 100 PDF pages. Each PDF page needs extractable text.
2. **Extract and detect.** The service extracts PDF text in sorted page order and normalizes Unicode to NFC and line endings to LF. Rules detect known PII forms. Optional local spaCy adds eligible person and context-specific location spans. Exact spans of the same type share evidence. Overlapping spans of different types remain separately reviewable.
3. **Resolve identities.** Deterministic rules compare names and nearby variants. An initial with a plausible unique anchor may become a proposal. Shared surnames and competing anchors can remain separate ambiguous mentions.
4. **Review.** The browser displays original extracted text, offsets, lines, and evidence. The reviewer marks every mention Redact or Keep and confirms, rejects, or detaches every proposed link. Link status and redaction are separate decisions. Exact-occurrence actions affect eligible pending mentions and preserve explicit decisions. Manual literals match case-insensitively in extracted text.
5. **Preview.** `POST /api/preview` validates all decisions, rejects Keep overlaps and known residual repeats, applies approved span replacements, and issues a receipt for the submitted choices. Editing a decision clears the browser preview.
6. **Release.** `POST /api/release` requires the latest receipt for matching decisions. The service recomputes redactions, reopens the UTF-8 TXT bytes, and builds a new PDF from sanitized text when supported. It reopens the PDF and checks extracted text, known approved and kept values, and generated object and stream integrity. Unexpected verification failures block release. Known PDF layout and font limits can leave verified TXT available.
7. **Summarize and download.** The summary path separately masks explicitly kept spans, validates the resulting text, and ranks source excerpts. It checks the proposed summary for provenance, known sensitive values, direct identifiers, and quasi-identifier signals. A failed check withholds the summary. The browser downloads the verified artifacts and any available summary. Successful release consumes the review.
